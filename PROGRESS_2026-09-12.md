### 2.2 OnePlus Nord Buds 2 Connection RCA & Resolution
- **RCA Findings**:
  1. *Cached Address Hijacking*: `~/.buds_controller_cache.json` stored Buds 3's UUID (`29F9439B-...`). When Nord Buds 2 connected via classic audio, the controller attempted to retrieve the cached Buds 3 address, hijacking the session and failing.
  2. *Permissive Match Fallback*: An `elif is_supported_device(p_name)` check matched any device in the catalog (Buds 3), overwriting the active profile back to Buds 3.
  3. *CoreBluetooth Hangs*: `connectPeripheral:options:` on macOS has no internal timeout. Calling it on an offline cached device hung the controller in `"Connecting..."` indefinitely.
  4. *31-Byte BLE Adv Packet Omission*: Nord Buds 2 uses GATT UUID `00001107-...`. Its advertising packet omits the 128-bit UUID due to BLE packet size limits, so scanning with 128-bit service UUID filters never discovered it.
  5. *Unreset Handshake*: `_handshake_started` was not reset on disconnect, blocking session setup packets upon device switching.
- **Fixes Implemented**:
  1. **Address & Handshake Invalidation**: Cleared `state.address = ""` and reset `_handshake_started = False` on every connect, disconnect, and manual disconnect event in `core/menubar.py` and `core/ipc.py`.
  2. **Strict Active Audio Device Binding**: In `attempt_fast_connect()`, the controller strictly checks `find_connected_supported_device()` from `IOBluetoothDevice` and matches only peripherals corresponding to the active audio device name.
  3. **5.0-Second Connection Timeout Guard**: Attached an `NSTimer` (5.0s) to `connectPeripheral:options:`. If CoreBluetooth hangs, the connection is cancelled, status is marked `"Connection Timed Out"`, and a targeted scan begins.
  4. **Targeted BLE Scan with Fast Pair Discovery**: Included 16-bit `FE2C_SHORT_UUID_CB` (`0xFE2C`) in service queries, and implemented an open scan (`scanForPeripheralsWithServices_options_(None, None)`) to capture advertising packets by name and Fast Pair data.

### 2.4 Pure Native Swift Implementation (`swift/`)
Developed an independent, zero-dependency Swift version alongside the Python app:
- **`swift/nordbuds_plus.swift`**: Standalone, runnable script directly inspired by `cracked-oneplus-buds`, but extended with full multi-device support (Buds 3, Nord Buds 2, Bullets, Enco), Fast Pair `FE2C` discovery, and sub-second packet dispatching.
- **`swift/Package.swift` (Swift 6)**:
  - **`OnePlusBudsCore`**: Pure Swift TLV framing (`Protocol.swift`), 82+ model catalog (`DeviceCatalog.swift`), CoreBluetooth state machine with timeout guards (`BluetoothController.swift`), and native `IOBluetooth` listener (`SystemAudioMonitor.swift`).
  - **`OnePlusBudsCLI`**: High-speed compiled CLI executable (`buds status`, `buds on`, `buds --game-mode on`, `buds --eq Bold`).
  - **`OnePlusBudsApp`**: Full native macOS Menu Bar App with AirPods popover UI, custom `BatteryPillView`, noise controls, and feature switches.
- **Performance Benchmark**:
  - **Compilation Time**: 1.7 seconds (`swift build -c release`).
  - **Binary Size**: `buds` = 280 KB, `OnePlusBudsApp` = 298 KB (vs ~150 MB Python app bundle).
  - **RAM Usage**: ~12 MB (vs ~160 MB Python + PyObjC runtime).
  - **Dependencies**: 0 external packages (native AppKit, CoreBluetooth, IOBluetooth, Foundation).
